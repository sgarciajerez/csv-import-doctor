## Profile notes

- Shopify says the first row contains column headers and columns are comma-separated.
- Shopify states that gift cards can't be created by importing a product CSV, although existing gift card details can be edited in bulk. The profile reports this only in create mode when `Gift card` is `true`.
- Shopify's import guide sets a 15 MB maximum for product CSV files. The app keeps a distinct 20 MB local analysis limit so it can explain the import-size error on files that still fit browser limits.
- [Shopify product import guide — 15 MB maximum](https://help.shopify.com/en/manual/products/import-export/import-products)
- Shopify's current guidance distinguishes required columns for product creation from updates; it also documents backward compatibility for older column names without listing all aliases on the current page. Do not infer an alias without a verified source/example.
- For creating products, `Title` is the only always-required column; adding variants also requires `URL handle`.
- For updates, `URL handle` and `Title` are required. Variant data can depend on `Option1 name` and `Option1 value`.
- Shopify says valid URL handles can contain letters, dashes, and numbers, and cannot contain spaces. The app warns on whitespace only and preserves the input; it does not reject other characters based on inference.
- Shopify limits each product to 250 tags, represented as comma-separated values in the `Tags` cell. The app warns above 250 non-empty entries on product-start rows and preserves the original cell.
- Shopify recommends avoiding accented characters and symbols in tags. The app currently detects accented Latin letters only and shows an informational recommendation; it does not classify them as invalid or propose changing language-specific tag text. Other symbols are not diagnosed because the guide does not define a precise character set for them.
- Shopify supports up to 20 barcodes per product or variant. In the current `Barcodes` column, semicolons separate values while `\\`, `\;`, and `\:` escape literal backslashes, semicolons, and colons. The app counts unescaped semicolons and preserves the cell.
- Shopify allows one collection per product and limits the `Collection` value to 255 characters. The app warns above that length on product-start rows, counts Unicode code points, and preserves the value.
- Shopify allows up to 250 product images and instructs CSV authors to use one row per image. The app counts nonblank `Product image URL`/`Image Src` cells across rows grouped by handle and warns once at the 251st entry. It does not include `Variant image URL` references because those can point to an image already listed for the product; consequently the warning is a lower-scope check when only variant-image URLs are supplied.
- Shopify requires image URLs to be publicly accessible over HTTPS without password protection. The app warns when a URL is malformed, non-HTTPS, or contains embedded username/password, but never requests it; successful local URL parsing does not prove that the image exists or is public.
- Shopify says product image filenames must not use the `_thumb`, `_small`, or `_medium` suffixes. The app checks the product-image URL pathname (not query parameters), warns, and preserves the URL. This check does not apply to `Variant image URL` because Shopify's suffix guidance is attached to the product image field.
- Inventory quantities must be numeric; the troubleshooting guide documents an import failure for non-numeric values and blank quantities when tracking. Because the product column table also lists 0 as the default for omitted quantity, the blank-quantity diagnostic is a warning rather than a blocker. Shopify documents that product CSV `Inventory quantity` only applies to stores with one location; the app shows one file-level informational note when any quantity is supplied, since it cannot inspect store locations. Shopify documents a blank `Inventory tracker` when inventory isn't tracked; when a tracker column is explicitly present but blank alongside a quantity, the app warns to confirm intent without claiming the quantity will be rejected or changed. An omitted tracker column is not diagnosed, especially in update mode where omitted columns can preserve existing values. Inventory policy accepts `deny` or `continue`. A custom fulfillment service requires a nonblank variant SKU; the app cannot verify that the service is configured in the shop.
- A blank `Price` has conflicting documentation: the troubleshooting guide lists it as an import error, while the product CSV table says the omitted value defaults to `0.00`. The profile warns on blank product/variant rows instead of blocking or inserting a price; image-only continuation rows are excluded from this check.
- Shopify recommends lowercase characters for custom fulfillment service names, replacing spaces with hyphens and removing periods or other punctuation. The profile warns on uppercase letters, whitespace, and punctuation, while preserving the value and requiring merchants to confirm the exact configured handle.
- Shopify's guide lists `shopify`, `shipwire`, and `amazon_marketplace_web` as Inventory tracker values, but says valid values "include" these. An unlisted value is informational only and may belong to a legacy or third-party integration; confirm with that integration rather than assuming it is invalid.
- Shopify lists lowercase `true` and `false` as accepted values for `Published on online store`, `Gift card`, `Charge tax`, and `Requires shipping`; the profile checks these and their verified legacy spellings. It warns on other nonblank spellings but preserves the value because the source does not detail case coercion.
- Shopify requires `Weight value (grams)` to be a number in grams without a unit or decimal places, and lists `g`, `kg`, `lb`, `oz` for the display unit. The profile warns on other nonblank spellings, covers the verified legacy `Variant Grams` field, and never converts the data.
- Shopify says image positions order images in ascending order from 1 and limits image alt text to 512 characters (125 or fewer is optimal). The profile warns on nonnumeric/below-1 positions and text above 512 Unicode code points, including image continuation rows; it does not reorder images or rewrite text.
- Shopify documents SEO title and SEO description limits of 70 and 320 characters. The profile warns only on product-start rows, counts Unicode code points, and preserves text without truncation.
- In overwrite updates, blank cells in included optional columns replace existing values with blanks; omitted columns preserve existing values. The app cannot see whether the merchant will select Shopify's overwrite option, so its notice is conditional.
- Changing a populated `Option1 value`, `Option2 value`, or `Option3 value` can delete existing variant IDs and create new ones. The app warns about the risk; it cannot compare values with the store's current data.
- Packed product length, width, height, and dimension unit form a group. Shopify documents errors for partial dimension values; four blanks on a variant update can clear saved dimensions. Setting `Requires shipping` to `false` clears saved dimensions even if the columns are omitted, and row values are ignored.
- Product rows with variants use a first row containing product-level data and continuation rows keyed by the same handle.
- Shopify's troubleshooting guide reports an import error when a product has duplicate variant option combinations. The analyzer compares exact option-value strings within the same exact handle; it does not normalize case or whitespace, and it preserves all rows and values.
- Additional image rows require the product handle; rows without a title can be product continuations or image rows depending on the other columns.
- The validator recognizes inventory CSVs with a `Location` column plus a documented inventory-only quantity field. It also recognizes wide â€œAvailableâ€ exports that have `Handle`, `Title`, at least two non-empty location columns with numeric/`Not stocked` values, and no known product data columns. A one-location candidate receives an informational warning and product checks continue because the pattern is ambiguous.
- The parser can accept other delimiters for analysis, but Shopify product CSV output is normalized to commas and LF line endings; the source format receives a warning. When automatic detection is ambiguous, the app blocks repairs and downloads until an explicit delimiter choice and reparses the local file before the result can be trusted.
- `fixtures/shopify-product-conflicting-aliases.csv` demonstrates mixed current and legacy spellings. The profile warns for those pairs while preserving the original header order and every value.
- `fixtures/shopify-product-current-headers.csv` records the current documented fixed headers plus examples of International, Markets, Google Shopping, and product metafield headers; the contract test ensures none are reported as unknown or misspelled.
- `fixtures/shopify-product-inventory-dependencies.csv` covers tracked and untracked rows, numeric and invalid quantities, policy values, custom versus built-in fulfillment services, a valid slug-style custom service, a service value with spaces and punctuation, and a tracker value outside Shopify's documented examples.
- `fixtures/shopify-product-duplicate-variant-options.csv` includes one repeated option tuple under the same handle and the same tuple under another handle; only the same-product duplicate is diagnosed.
- `fixtures/shopify-product-blank-price.csv` covers blank product and variant prices plus an image-only continuation row, which must not receive a price warning.
- `fixtures/shopify-product-boolean-values.csv` covers valid and unexpected boolean spellings on product and variant fields; a test also covers the verified older `Published`, `Variant Requires Shipping`, and `Variant Taxable` headers.
- `fixtures/shopify-product-weight-values.csv` covers blank and valid weight fields, decimal/unit-bearing gram values, unsupported display units, and continuation-row handling; the legacy `Variant Grams` header is covered in a focused test.
- ixtures/shopify-product-image-metadata.csv covers image positions 1, 2, zero, and nonnumeric text, plus the 512-character boundary and a 513-character alt text across image rows.
- Market exports can contain `Included / [Market]`, `Price / [Market]`, and `Compare At Price / [Market]`; Shopify exports only markets whose active catalog is not shared with another market. The app recognizes these dynamic headers and preserves their values without trying to validate catalog pricing.
- Product metafields are supported in named forms such as `<name> (product.metafields.<namespace>.<key>)` and `NAME; (product.metafields.custom.KEY)`, or as `product.metafields.<namespace>.<key>`. The source page shows both named spellings; the app recognizes and preserves them but cannot validate values without the store's metafield definitions. Product references may require an existing referenced product; the app cannot verify that locally.
- Variant metafields are not supported by product CSV. Recognizable `variant.metafields.*` headers receive a warning; values and header text remain unchanged. Unknown columns must remain unchanged unless a documented rule says otherwise.
- Shopify accepts UTF-8 and recommends LF line endings.
- Older templates may use other header names, but the current guide does not enumerate all aliases. The exact aliases listed in `LEGACY_HEADER_ALIASES` are supported only because Shopify's official older template example verifies them; do not infer other mappings from name similarity alone. If a current header and its verified legacy alias both appear, emit an advisory because Shopify does not document whether one column takes precedence.
- This initial profile will only implement rules supported by the source. Unknown columns are preserved; duplicate SKU values are warnings at most.
