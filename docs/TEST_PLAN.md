# Test plan

Initial core coverage:

- Detect Shopify Markets and B2B catalog CSVs using `Catalog Title` plus fixed-price/publication or quantity-rule/volume-pricing headers; skip product-profile checks in create and update, preserve headers/cells on round-trip, and do not false-positive product files containing only shared `Handle` and `SKU` fields. Authenticated E2E checks both catalog warnings and the B2B source link.
- Detect customer CSVs using `Email` plus customer-specific columns, including the shared `Tags` header; test create/update, source attribution, and round-trip. For unrelated headers and a non-comma delimiter, emit only the unrecognized-format note and confirm the downloaded CSV preserves that delimiter; a likely one-character product-header typo should still trigger product diagnostics.
- Detect Shopify order exports using `Name` plus at least two order-specific columns; include shared `Email`, `Phone`, and `Tags` to ensure order detection precedes customer detection. Test create/update, official source attribution, continuation rows, exact round-trip, and a product-shaped file with order-like custom columns to prevent false positives. Authenticated E2E checks the merchant-facing notice/source and that download preserves the order CSV cells.
- Shopify App Store entrypoint: verify the public root is accurate and branded, links merchants to Shopify Admin, contains no shop-domain input or scaffold placeholders, and does not initiate installation outside Shopify.
- Image URLs: keep malformed, relative, non-HTTP(S), and credential cases distinct from HTTP scheme ambiguity; HTTP is informational because Shopify guidance differs on the scheme. Check recognizable Google Drive or Dropbox preview links locally, ensure direct-download query patterns remain clear, and verify URLs and file contents are never sent to image hosts.
- CI on pushes and pull requests to `develop` and `master` installs the root core workspace and the Shopify app from their lockfiles, then runs lint, typecheck, unit tests, and production build for both; authenticated E2E remains a separately configured gate.
- When a machine cannot resolve Shopify CLI's temporary tunnel hostname, authenticated E2E can use `PLAYWRIGHT_HOST_RESOLVER_RULES` for Chrome's host resolver and `PLAYWRIGHT_APP_SERVER_URL` for direct local webhook requests; do not commit tunnel-specific hostnames or IP addresses.
- Diagnostic contract over every CSV fixture in both create and update modes: require stable IDs, complete issue metadata, valid row/column references, source and profile version on Shopify findings, and a catalog entry for every emitted rule; map Papa Parse parser codes to the documented parser rule template.
- Pinned Shopify product template header fixture: require exact current/template spellings and dynamic market/metafield examples to avoid typo, unknown-header, case, whitespace, unsupported-option, or unsupported-media diagnostics. Re-download and compare the official template separately when Shopify's published source changes.
- Header identity and documented enum values use locale-independent case normalization; simulate a Turkish default locale and verify mixed-case ASCII `I` headers still match Shopify's profile and duplicate detection.
- Google Shopping headers are limited to the exact names enumerated by the current Shopify guide or present in its downloadable template; a one-character misspelling gets a low-confidence suggestion, unrelated names stay informational, and round-trip preserves all headers and cells.
- Authenticated embedded-admin E2E loads the Google Shopping header fixture and checks that the probable typo and unrecognized-header diagnostics are visible to the merchant.
- The exact older-template image aliases `Image Src` and `Image Alt Text` resolve to current `Product image URL` and `Image alt text`; test current-only, legacy-only, and mixed-header behavior, preserve both columns when mixed, and count a legacy image column only once toward the product-image limit.
- For `Option1/2/3 LinkedTo` and downloadable-template `Option1/2/3 Linked To`, test each spelling alone and together; mixed spellings produce an ambiguity warning, preserve both values, and validate each link format.
- UTF-8 BOM, explicit rejection of invalid UTF-8, quoted delimiters, escaped quotes, embedded newlines, and Unicode.
- Duplicate headers and rows with too few or too many cells.
- Empty/malformed input and ambiguous delimiter selection, including blocked repairs/downloads until explicit user confirmation and reparse.
- Browser workflow rejects invalid UTF-8 and blocks both downloads when the 100,000-row analysis limit is exceeded.
- Measure near-20 MB local long-cell and 100,001-row workflows in E2E; assert that the 15 MB Shopify limit is diagnosed, the 20 MB local cap is enforced, and preview truncation does not alter exported CSV content.
- Create/update profile requirements and product variant continuation rows.
- Option integrity: on a product-start row, an explicit `OptionN name` with a blank matching value receives a sourced advisory in create and update mode; valid `Default Title` values and continuation rows with omitted option names stay clear, with all cells preserved.
- In authenticated E2E, verify the import-mode control and file input are reachable by tab and the create/update selector changes via keyboard; keep the full manual keyboard, screen-reader, contrast, and responsive review as a separate requirement.
- In authenticated E2E, inject axe-core into the embedded app and require zero WCAG 2.0 A/AA, WCAG 2.1 A/AA, and WCAG 2.2 AA violations on the initial analyzer, analyzed-result, applied-repair, pending-delimiter, and confirmed-delimiter states. Keep other interaction states and manual assistive-technology review separate.
- In the built app's HTTP integration test, start the production React Router server with a synthetic Shopify secret, seed one synthetic session row, send a correctly signed `shop/redact` request, and verify that only that row is deleted; then send an invalid HMAC and require 401. Use a randomly generated fake shop and session ID, never the development shop.
- At a 390 px viewport, analyze the full current-header fixture; verify the page does not overflow horizontally and the preview caps its visible header columns at 20. This automated check does not replace review on actual narrow devices.
- Record WCAG contrast calculations for authored text and control colors in `docs/ACCESSIBILITY_REVIEW.md`; verify focused file input has a computed outline in authenticated E2E. Polaris theme surfaces, badges, screen-reader output, and other browser/device combinations remain manual review items.
- Authenticated keyboard flow: from the repair-search control, use Tab to reach the first repair checkbox, Space to select it, Tab to reach the apply button, and Enter to apply. Assert focus and the applied-status announcement; manual screen-reader review remains separate.
- Before claiming importer-level compatibility, manually compare `fixtures/shopify-product-import-smoke.csv` with the Shopify development-store importer. Confirm it creates one draft product with two Size variants, then remove that synthetic product. This is a manual store mutation and requires the owner’s explicit product decision; automated app tests must never trigger it.
- For dynamic `Included / [Market]` product columns, verify case-insensitive `true`/`false` and blank values remain clear, other nonblank values produce an informational recommendation only, and all cells remain unchanged. The message must not claim Shopify will reject the value because its guide does not enumerate accepted spellings.
- Compare `fixtures/shopify-product-current-headers.csv` against Shopify's downloadable template header row checked 2026-10-16; no exact template column should be classified as unknown or misspelled. Keep tax-code and unit-price measure values unchanged unless the guide documents a validation rule.
- Keep the documented `Barcode` plus `Barcodes` combination as an import error. If `Variant Barcodes` from the downloadable template appears with any other barcode header spelling, emit only a sourced review warning because Shopify does not document the combined behavior; preserve all values.
- For plural barcode cells, recommend review when a value repeats within that cell, including when the same value is labeled with different documented barcode types or once with the default `Custom` type. Honor escaped separators, avoid comparing distinct CSV rows, and preserve exact source text.
- For recognized `gtin:`, `upc:`, `ean:`, `isbn:`, `asin:`, and `custom:` barcode prefixes, test Shopify's documented type-specific lengths and character sets at valid boundaries and just outside them, including a 255/256-character Custom value. Do not validate registry assignment or check digits; preserve every source value.
- The authenticated E2E analyzes that smoke fixture in create mode and confirms its two product/continuation rows have no profile diagnostics; this does not substitute for the manual importer comparison.
- In authenticated E2E, open the in-app merchant guide from the analyzer, verify the non-import guarantee, FAQ on diagnostic limits and inventory CSVs, and size/row limits, then return to the analyzer; the route remains protected by the embedded app's parent authentication.
- Required values: create rows need a Title; update product rows need Title and an existing URL handle; continuation rows containing data need a handle for association. Ensure blank Title on a continuation row that repeats its handle remains valid, and preserve all supplied values.
- Sourced field limits at exact boundary and over-limit: URL-handle whitespace, 255-character Collection values, 250 comma-separated product tags, and 20 semicolon-separated barcodes including escaped separators; unit tests confirm the analyzer preserves the original cell, and E2E confirms limit messages are visible.
- Tags: detect accented Latin characters in composed and decomposed Unicode spellings and punctuation/symbols other than hyphens; report as information in create and update without claiming import failure or changing values; leave ordinary spaces, hyphens, and letters from other scripts clear.
- Product category IDs: recognize valid root and nested IDs from the pinned Shopify taxonomy, inform on an unknown ID without claiming Shopify rejects it, preserve all values, and do not diagnose full breadcrumbs that may be localized.
- Taxonomy-linked options: warn on nonblank `Option1/2/3 LinkedTo` values that omit the documented `product.metafields.shopify.` prefix or taxonomy attribute key; accept a documented key and blank optional link fields, preserve all values, and do not validate linked values against store-specific metaobject definitions.
- Markets pricing: warn when a nonblank `Compare At Price / [Market]` or `Compare-at price / [Market]` has no corresponding `Price / [Market]` column or the same-row price is blank; accept a nonblank fixed price and blank compare-at value; test multiword market names, and warn if both documented compare-at spellings occur for the same market while preserving all cells. For an unambiguous numeric pair, recommend reviewing a fixed compare-at value equal to or below the market's fixed price; skip conflicting aliases, duplicate price headers, blanks, and nonnumeric values, and preserve both cells.
- Sale pricing: recommend review when a valid numeric base or market compare-at price is equal to or lower than its corresponding price; allow a higher compare-at price, skip blank or malformed values and ambiguous alias pairs, cover verified legacy headers and both create/update modes, and preserve both values without claiming import failure.
- Product media: recognize explicit `Video URL`, `Product video URL`, `3D model URL`, and `Product 3D model URL` columns as unsupported by product CSV media import; test case/whitespace header diagnostics, confirm standard product image URLs stay valid, and preserve all values.
- Unsupported fourth and later product options: detect `OptionN name`, `OptionN value`, and `OptionN LinkedTo` for `N > 3` regardless of capitalization; if the header also has surrounding whitespace, emit both the unsupported-option and whitespace diagnostics. Verify that no form produces a probable typo suggestion and preserve every header and cell.
- Inventory-related values: when `Inventory tracker=shopify`, report an error if exactly one of `Continue selling when out of stock` and `Fulfillment service` is supplied; accept both supplied or neither (documented defaults), and do not apply this dependency to another tracker value. Preserve values and identify the row.
- Product image maximum at 250/251 rows for one handle, including continuation rows; confirm only one warning is emitted and values are preserved. Verify variant image references are documented as outside this count.
- Image URL severity contract: HTTPS is accepted structurally; HTTP emits the informational scheme note; relative/malformed, non-HTTP(S), and credential-bearing values emit a warning. Cover product and variant image columns and verify no supplied URL is requested.
- Product image filename suffixes: test `_thumb`, `_small`, `_medium` with and without extensions, ignore query-string matches, preserve URLs, and keep variant image references outside this product-field-specific check.
- Product money formatting: test `Price`, `Compare-at price`, `Cost per item`, verified legacy price aliases, and exact fixed-market price/compare-at headers; accept integer, zero, signed, and dot-decimal numeric examples, warn on currency symbols/codes and nonnumeric text as recommendations, preserve all values, and verify the advisory is visible in E2E. Cover both documented market compare-at spellings.
- Unit pricing: if any of the four documented measurement values is populated, recommend reviewing the quartet when another header or value is missing; keep a complete quartet and all-blank quartet clear, skip duplicate headers, cover create/update, and preserve all values. Do not infer positivity or measurement-unit compatibility; verify the sourced advisory is visible in E2E.
- Gift cards: verify `Gift card=true` produces a sourced blocking diagnostic in create mode, does not produce that diagnostic in update mode, and preserves the cell; confirm the restriction remains distinct from boolean spelling checks.
- Inventory tracking: warn when a nonblank quantity is paired with an explicitly blank current or verified legacy tracker header; preserve the cells, do not flag omitted tracker columns or conflicting current/legacy aliases, and keep valid tracked rows clear.
- Single-location inventory field: emit one file-level informational note when at least one product `Inventory quantity` value is nonblank; do not emit it when all values are blank or when a separate inventory CSV is detected.
- Verify unknown columns and repeated SKUs are preserved and are not fatal errors.
- CSV parse/serialize round-trip preserves a deterministic edge-case cell matrix with both comma and semicolon delimiters, including empty cells, embedded delimiters, quotes, LF/CR/CRLF, boundary spaces, and Unicode; formula-like values remain unmodified absent an explicit export policy.
- Repairs: apply only selected proposals to a copy, verify the source value and column header still match, reject stale proposals, revalidate, and undo without overwriting a changed or differently headed target.
- Browser bundle has no Node-only imports; analysis makes no network requests.
- File lifecycle: clear the file input so the same file can be selected again; keep a `File` reference only while an ambiguous delimiter needs reparsing, and release it after ordinary success, confirmed reanalysis, cancellation, parse/runtime failure, or setup failure. A unit test checks the reference-retention policy, and the authenticated E2E exercises confirmed reanalysis. Verify the worker terminates on cancel and when navigating away while analysis is pending.
- Privacy transparency: verify the embedded UI links to the public privacy page, which discloses browser-only CSV processing, the Shopify session fields actually stored, current empty API scopes, retention behavior, and release-only facts still pending.
- Compliance webhooks: verify TOML subscriptions for all three mandatory topics, `401` for unsigned/invalid HMAC POSTs, authenticated handling, idempotent session deletion for `SHOP_REDACT`, and 200 responses for customer requests when no customer data is stored. Node unit tests generate a fixture-only HMAC, pass it through Shopify's React Router `authenticate.webhook` and the same compliance handler used by the HTTP route, and verify a changed signed raw body is rejected. Before distribution, also validate delivery against the actual local app configuration or Shopify's webhook tooling.
- Shopify API version: at each quarterly review, verify that `shopify.app.toml` webhook `api_version` and the server `ApiVersion` enum use the selected supported stable version; never use a release candidate for production.

Accessibility review before closing R10-07:

- Navigate the complete upload, analysis, filter, repair, undo, and download flow with keyboard only; verify focus remains visible and operable.
- With a screen reader, confirm analysis start/completion/cancellation, errors, repair updates, and table headers are announced in a useful order.
- Check color contrast for body text, errors, controls, and focus indicators, then inspect narrow viewport layouts with many CSV columns.
